# CleanDoc 面试演示脚本（OBS 录屏 · 口播版）

> 用途：长沙迭亦「AI 平台技术负责人」面试演示活证据（JD 职责③：施工文书自动生成场景）
> 时长：约 4-5 分钟 ｜ 形式：OBS 录屏 + 口播讲解
> 核心：**讲「怎么做的」而非「做了什么」**——双路检索决策、溯源设计、工程落地是加分点

---

## 演示前 5 分钟 Checklist

- [ ] `docker start archrag-neo4j`（图谱路前置，决策①）——**必须**
- [ ] `docker start cleandoc`（应用容器）——**必须**
- [ ] 浏览器打开 `http://localhost:8502`，确认页面加载
- [ ] 先手动跑一次生成（约 90s，模型常驻预热），确认正常出结果
- [ ] 清空页面回到初始表单状态（刷新页面）
- [ ] OBS 开好：录屏源 = 浏览器窗口（见 OBS 配置）

## 口播脚本

### 开场（30s）
> 「我做一个洁净室施工技术交底的自动生成 MVP——输入项目参数，自动生成带规范依据的施工交底草稿。背后是一套双路检索 + 融合生成的 RAG 架构。」

**【操作】**：展示页面表单（项目/分项/部位/参数/交底类型）

### 第一段：双路检索的动机（1min）
> 「交底要同时满足两件事：一是**规范依据**（GB 50073 这类洁净室规范），二是**本项目特定要求**（这个药厂净化空调的实际参数）。所以我把检索拆成两路：
> 第一路查规范库——复用我之前的 ArchRAG 系统，三路召回（向量+BM25+知识图谱），图谱能给出实体关系，比如『洁净室→严禁→散热器采暖』这种规范约束；
> 第二路查项目库——每个项目的资料单独建索引，向量+BM25 融合，保证召回的是本项目自己的参数。」

**【操作】**：点击「生成交底」→ 等待期间继续讲（约 90s）

### 第二段：证据链与溯源（1.5min）
> 「生成过程中我把中间结果全保留下来——这是它和普通 ChatGPT 问答的本质区别：
> 第一路查出来的规范要点（点开①）——这是问答台本整理后的，带引用编号；
> 第二路项目背景（点开②）——这是本项目自己的资料原文；
> 关键在最后：交底正文里的 `[1][2]` 这些编号，**每一个都能点**（点击 `[4]` 跳转溯源表）——下面是引用溯源表，这一条对应规范库 test.pdf，这一条对应『示例药厂_净化空调.md』的段落 14。做到**每个结论都有出处**，不是模型编的。」

**【操作】**：依次点开 ①② 展开 → 点击正文 `[4]` 演示锚点跳转 → 指向溯源表两行

### 第三段：工程细节（1min）
> 「几个工程决策：
> 一是**零修改母系统**——我的 ArchRAG 跑在 Docker 里只读挂载，CleanDoc 通过适配层 import 复用，两套系统物理隔离，规范库永远只读；
> 二是**参数冲突显式提示**——比如表单写 20±2℃、资料写 22±2℃，交底里会主动标注『以设计图纸为准，需项目总工核定』，不静默覆盖（指向工程概况段）；
> 三是**500 字符切片**——嵌入模型 BGE 是 512 token 上限，切 500 字符刚好对齐，这是检索质量的硬约束。」

### 收尾（30s）
> 「整个 MVP 辅助起草、需人工复核签字——这是我对 AI 生成文书的诚实定位。技术栈：Streamlit + BGE 嵌入 + DeepSeek 生成 + Neo4j 图谱，全部本地跑在 3090 上。」

## OBS 录屏配置

- **来源**：窗口捕获 → 选择 Chrome/Edge（含 localhost:8502 标签页）
- **麦克风**：若面试是腾讯会议口播，需同时录系统 + 麦克风（OBS「设置→音频」开两个）
- **画布**：1920×1080
- **输出**：MP4（OBS 默认），路径自选

## 演示纪律（决策⑲）
- 开播前**确认极光 VPN 已关**或浏览器加 `--proxy-bypass-list="<-loopback>"`（loopback 端口被代理劫持是已知坑）
- 演示时**不要切走浏览器**做别的（会录进画面）
- 生成过程 90s 是展示点：讲双路/讲切片，别冷场
